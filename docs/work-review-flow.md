# 근무 등록·검토·수정 흐름

| 단계 | 알바생 | 매니저 | 사장님 |
| --- | --- | --- | --- |
| 임시저장 | 직접 수정·삭제 가능 | 근무 검토 달력에서 조회 가능, 승인 대기에는 미포함 | 근무표에 미표시 |
| 이번 달 일괄 제출 | 승인 대기, 직접 수정 대신 수정요청 가능 | 최종 승인 또는 사유와 함께 반려 | 근무표에 미표시 |
| 반려 | 수정 후 임시저장하고 다시 제출 | 재제출 후 검토 | 근무표에 미표시 |
| 최종 승인 | 승인 완료 표시, 직접 수정 불가 | 지급 전 수정·삭제 가능 | 검토 완료 근무표에 표시, 급여 계산에 포함 |
| 승인 후 매니저 수정 | 수정 완료 표시 | 수정 완료 표시, 재수정·삭제 가능 | 수정 완료 표시 및 변경 전후 이력 확인 |
| 승인 후 매니저 삭제 | 근무 달력에서 제거 | 달력에서 제거, 삭제 이력 유지 | 근무표에서 제거, 삭제 전 내용과 처리자·시각은 이력에 유지 |
| 급여 지급 완료 | 조회 | 관련 근무 수정·삭제 차단 | 지급 완료 내역 조회 |

사장님은 근무마다 다시 승인하는 대신, 검토 완료 근무표를 확인한 후 급여 화면에서 계산 → 확정 → 지급 완료를 처리한다.
매니저 본인의 근무는 기존 정책대로 저장 즉시 승인 처리되어 사장님 근무표에 표시된다. 본인 근무 수정도 동일한 수정 RPC를 사용한다.
제출 상태의 수정요청을 매니저가 적용해도 최종 승인은 별도로 해야 한다.

## 변경 확인

- 사장님 근무표와 매니저 근무 검토에 선택한 근무 월의 수정·삭제 이력을 표시한다.
- 이력에는 대상 직원, 근무일, 처리자, 처리 시각(한국 시간), 변경 전후 출퇴근·휴게시간·메모를 표시한다.
- 사장님 근무표와 변경 이력은 화면을 보고 있는 동안 30초마다, 창으로 돌아올 때 갱신한다. 푸시·이메일 알림이나 읽음 확인 기능은 아니다.
- 승인 상태는 급여 집계를 위해 유지하며, DB가 기록한 `manager_modified_at`을 기준으로 화면 문구를 ‘수정 완료’로 구분한다.
- 삭제 이력은 원본 근무와 별개로 보존한다. 클라이언트에서 이력을 작성·수정·삭제할 수 없다.
- 이력은 0019 적용 이후부터 수집한다. 과거 변경 내역은 복원하지 않는다.

## 급여 영향과 적용

수정·삭제는 근무 변경, 이력 저장, 기존 급여 재계산을 한 트랜잭션으로 처리한다. 관련 확정 급여는 계산 완료로 되돌려 사장님이 다시 확정하도록 한다. 월말 근무로 다음 달 주휴수당이 바뀌면 해당 달의 기존 급여도 재계산한다. 영향을 받는 급여 중 지급 완료 건이 있으면 전체 작업을 거절한다. 아직 계산하지 않은 급여는 나중에 계산할 때 반영한다.

0018까지 적용한 DB에 `0019_work_record_history.sql`을 실행해야 한다. 이 환경에서는 원격 DB 적용과 DB 통합 테스트를 실행하지 못했다.

## DB 적용 후 확인 항목

1. 알바생 임시저장 → 제출 → 매니저 승인: 사장님에게는 승인 이후에만 표시되는지 확인한다.
2. 승인 근무 수정: 세 역할의 달력에서 ‘수정 완료’와 변경 시간이 표시되고, 매니저·사장님 이력에 전후 내용이 남는지 확인한다.
3. 확정 급여가 있는 승인 근무 삭제: 근무가 제거되고 급여가 재계산·확정 해제되며 삭제 이력이 남는지 확인한다.
4. 지급 완료된 근무 및 다음 달 지급 급여에 영향을 주는 월말 근무 수정·삭제: 거절되고 기록·이력·급여가 모두 그대로인지 확인한다.
5. 다른 매장 매니저·알바생의 RPC 호출, 이력 직접 쓰기: 거절되는지 확인한다.
6. 같은 근무를 두 화면에서 열고 먼저 수정한 후 오래된 화면에서 저장·삭제: 충돌 오류가 표시되는지 확인한다.
7. 매니저 본인의 근무 달력에서 수정해도 변경 이력과 급여 재계산이 동일하게 동작하는지 확인한다.
